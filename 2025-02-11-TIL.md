### JDBC

- JAVA로 데이터베이스 연동하는 방법(api)
- 클래스와 인터페이스의 집합
- JDBC Driver(Class)
    - 우리가 만드는 프로그램과 데이터베이스를 잇는 코어 역할
- database를 교체할 때 원래 관련된 코드를 다 변경해야 하지만, JDBC 를 활용하면 이에 상관없이 같은 처리가 가능함
- `jar`
    - java archive
    - 인터페이스, 클래스 등이 모여있음

### JDBC 전체 실행 과정

1. Driver Loading
    1. 프로그램에서 1번만 수행
    
    ```java
    package first;
    
    public class FirstConnect {
        public static void main(String[] args) {
            try {
                Class.forName("oracle.jdbc.driver.OracleDriver");
                System.out.println("Driver 로딩 성공");
            } catch (ClassNotFoundException e) {
                System.out.println("Driver를 찾을 수 없습니다.");
            }
        }
    }
    
    ```
    
2. DBMS와 연결
    1. 연결 성공 시 객체가 생성됨
    2. 만들어지는 객체의 클래스는 java.sql.Connection
    3. 어떤 데이터베이스에 접속하는지에 관한 정보 → JDBC URL
        1. “jdbc:데이터베이스 종류:” 까지 공통
        2. 이후 사용하는 데이터베이스에 따라 달라짐
    4. id/pw가 필요함
    
    ```java
    package first;
    ```

3. Statement 생성
    1. Statement
        1. 단순하나 기능상으로는 부족
        2. 잘 사용되지 않음
    2. PreparedStatement
        1. SQL Injection 방지 가능
        2. 편리성, 효율성
4. Query 실행 및 결과 처리
    1. executeUpdate()
        1. SQL - CUD
    2. executeQuery()
        1. SQL - R
    - 실행하면 데이터베이스에서 데이터를 가져오고 커서(ResultSet)가 생김
    
    ```java
    ResultSet rs = statement.executeQuery()
    rs.next() //한 줄 씩 내림
    rs.getString('btitle') // 현재 위치의 해당 컬럼 데이터
    ```
    
5. 리소스 해제
    1. 사용된 자원을 해제해야 함
    2. 가비지 컬렉션이 메모리 회수 안해주나?
        1. 자바만 쓰는 프로그램이 아닌 외부 sql을 연동하여 사용하고 있어서 직접 해줘야 함

```java
package first;

import java.sql.*;

public class FirstConnect {
    public static void main(String[] args) {
        try {
            Class.forName("oracle.jdbc.driver.OracleDriver");
            System.out.println("Driver 로딩 성공");

            Connection con = null;
            String JDBC_URL = "jdbc:oracle:thin:@localhost:1521:xe";
            con = DriverManager.getConnection(JDBC_URL,"C##DEV","1423");
            System.out.println("데이터베이스 연결 성공");

            String sql = "select * from book";
            PreparedStatement pstmt = con.prepareStatement(sql);
            ResultSet rs = pstmt.executeQuery();
            if(rs.next()) {
                System.out.println(rs.getString("btitle"));
            } else {
                System.out.println("검색 결과가 없습니다.");
            }

            rs.close();
            pstmt.close();
            con.close();
        } catch (ClassNotFoundException e) {
            System.out.println("Driver를 찾을 수 없습니다.");
        } catch (SQLException e) {
            throw new RuntimeException(e);
        }
    }
}

```

### Transaction

- jdbc를 이용해서 설정하려면
    - Connection에 설정

```java
conn.setAutoCommit(false); //transaction 시작
// 위 구문 없이 connection이 정상 종료되면 conn.commit()으로 간주
```

```java
package first;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.SQLException;

public class TransactionTest {
    public static void main(String[] args) {
        try {
            Class.forName("oracle.jdbc.driver.OracleDriver");

            Connection conn = null;
            String url = "jdbc:oracle:thin:@localhost:1521:xe";
            String user = "C##DEV";
            String password = "1423";

            conn = DriverManager.getConnection(url, user, password);
            conn.setAutoCommit(false);
            String sql = "insert into membertbl values(?,?)";
            PreparedStatement ps = conn.prepareStatement(sql);
            ps.setString(1, "1");
            ps.setString(2, "홍길동");

            int res = ps.executeUpdate();

            if(res == 1) {
                System.out.println("처리완료");
            }

            conn.commit();

            conn.close();
            ps.close();
        } catch (ClassNotFoundException e) {
            System.out.println("클래스가 없어요");
        } catch (SQLException e) {
            System.out.println("SQL 이슈");
        }
    }
}

```

### Layered Architecture

계층에 따라 역할이 나뉘어져 있으며 일반적으로 아래 4계층을 많이 사용함

- Presentation Layer
    - 내가 작성한 프로그램 중 사용자에게 보여지는 레이어
    - 입출력 처리
    - View, Controller
- Business (Logic) Layer
    - 로직 처리
    - Persistence Layer에서 데이터를 가져와 로직을 수행하고 이를 Presentation Layer에 전달하는 일만 함
    - Service, Domain Model
- Persistence Layer
    - 데이터의 영속성을 구현하고자 데이터 출처를 주 관심사로 둠
    - Repository, DAO
    - DB 접근
- Database Layer
    - 데이터베이스가 위치한 계층
    - MySQL, Oracle, …

### MVC Pattern

소프트웨어 디자인 패턴으로 어플리케이션(서비스)을 세 개의 영역으로 분할, 고유한 역할을 부여하는 방식임.

- M(Model)
    - Data Model(VO)
    - Service Model(로직 처리 전담 객체)
- V(View)
    - 입/출력 담당(Presentation Layer)
- C(Controller)
    - View와 Model을 연결해주는 역할
    - 시스템 흐름제어 담당
